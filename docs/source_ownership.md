# Documentation ownership and regeneration

This file is the public ownership map. The executable policy is
`inst/dev/documentation_policy.R`; it generates both
`docs/public_documentation_manifest.json` and the installed
`inst/documentation_manifest.json`. Do not edit either manifest by hand.

## Public canonical documentation

`README.md` is the entry point. The maintained guides in `docs/` are
`getting_started.md`, `bundle_concepts.md`, `ingestion.md`,
`sessions_and_ops.md`, `promotion_and_provenance.md`, `recipient_audit.md`,
`python_bridge.md`, and `extension_engineering.md`. The platform-agnostic
library in `inst/onboarding/` is installed package documentation. These files
are authoritative for their stated topics.

Dataset-specific collaborator guides live outside the package repository and
are not canonical package documentation or installed onboarding.

The current architecture entry point is installed
`inst/onboarding/SYSTEM_OVERVIEW.md`; the pack-authoring entry point is
`docs/operation_pack_sdk.md` and installed `sdk/operation-packs/GUIDE.md`.
`interface.json` and `callbacks.json` distinguish public and invocation-scoped
surfaces. `R/operation_pack_sdk.R` and `R/operation_pack_sdk_testing.R` own the
public helpers; `src/sdk_scaffold.c` owns Linux atomic no-replace publication.
The SDK capability and recipe references are generated by
`inst/dev/generate_operation_pack_sdk_catalog.R`, not edited manually.
PyBench's installed `sdk_authoring.md` owns the Python authoring surface.

Scientific method tests belong to their packs; generic authority remains core
owned. Documentation changes must not silently repin the standard profile or
change an official pack. Source locks and installed instance receipts represent
different identities.

`docs/operation_packs.md` and `R/operation_packs.R` own the public operation-pack
v1 ABI. The authoritative installed schema is
`inst/protocol/operation-pack-v1.schema.json`; external packages extend the
runtime overlay and never patch the core `.wb_op_catalog()` owner.
The schema and canonical fixtures under
`inst/protocol/fixtures/operation-pack-v1/` own the cross-language backend,
Python distribution normalization, entry-point group/name, and runtime
attestation checkpoint. PyBench mirrors them byte-for-byte; it does not redefine
their R semantics.

`R/operation_packs_v2.R`, `R/operation_packs_v3.R`, and their transition and
backend adapters own the closed successor ABIs. ABI v3's four shared files are
the manifest, request, receipt, and identity corpus under `inst/protocol/`;
PyBench mirrors those exact bytes and independently owns its v4 runtime
sidecar. `docs/operation_pack_v2_protocol.md` and
`docs/operation_pack_v3_protocol.md` are the corresponding public semantic
maps. Earlier protocol identities remain immutable.

`R/cell_set_consumption.R` owns catalog-driven durable named-cell-set
resolution, membership identity, and replay preflight for both core and pack
operations. Individual runners do not own cell-set provenance bindings.
`R/operation_pack_python.R` owns the R-side Python adapter: explicit discovery,
identity/runtime audit, capability construction, transition preparation, and
typed failure mapping. `R/pybench_transition.R` remains the sole isolation,
mutation-audit, and atomic-publication owner. PyBench owns distribution entry
point activation and capability-bound payload writes; neither side creates a
parallel catalog or committed-bundle writer.

## Generated public reference

`man/` is generated from roxygen comments beside canonical R implementations.
`R/operation_docs.R` is generated from `.wb_op_catalog()` through
`wb_op_interface()`. `docs/schema_catalog_reference.md` is generated from
durable schema declarations. The operation, getter, plot, wrangler, primitive,
artifact, mutation, parameter, recipe, semantic, compatibility, and graph
references in `docs/` are generated by the catalog writers in `R/`.

## Internal and obsolete material

Historical drafts, handoffs, benchmark notes, development plans, protocol v1
notes, debug media, and former onboarding templates live under `archive/`.
That directory is deliberately excluded from the source package. Backups are
removed rather than retained as parallel documentation.

## One regeneration and verification entry point

From the repository root run:

```sh
Rscript inst/dev/regenerate_public_docs.R --check
```

Without `--check`, the command regenerates roxygen, operation docs, the schema
catalog, semantic catalogs/graphs, and both manifests. `--check` performs the
same work in a temporary copy and fails if tracked generated bytes would change.
The command fixes generated timestamps to `source-controlled`, so separate
processes produce byte-identical output.

The source-tarball policy is also executable: it keeps code, metadata, MIT
license files, the package-native `inst/CITATION`, public docs, installed
onboarding, and the operation-pack v1/v2/v3 and PyBench protocol schemas and
canonical fixture corpora.
Repository-level `CITATION.cff` remains
the canonical software citation for hosting services but is excluded from the
R source tarball because R treats that top-level filename as non-standard. The
policy also excludes archives, coordination, editor state, caches, build
products, backups, and local output.
