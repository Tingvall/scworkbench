# Source ownership

Runtime behavior and durable schemas must not depend on R source collation
order. A function, schema table, or generated API reference has one canonical
owner.

## Runtime functions

- Every top-level function name under `R/` has exactly one definition.
- Package-wide helpers such as `%||%` and `.wb_require_cols` belong in
  `R/internal_contracts.R`; feature files consume them and do not redefine
  them.
- Public functions are documented beside their canonical implementation.
  `NAMESPACE` and `man/` are generated from that source with roxygen2.
- A duplicate is permitted only when `test_source_ownership_contract()` names
  it explicitly with a narrow, non-empty compatibility reason. There are no
  current exceptions, and stale exceptions fail the release gate.

## SQLite schema

- `R/schema_core.R` owns core bundle DDL and fresh-schema orchestration:
  datasets, cells, cell-set membership/styles, spaces, features, matrices, and
  matrix-cell membership.
- `R/matrix_fragments.R` owns the fragment registry, ordered JSON identities,
  normalized fragment membership tables, schema migration, fragment IDs, and
  `wb_register_matrix_fragment()`.
- `R/artifacts_schema.R` owns artifact registry DDL. `wb_migrate_artifacts()`
  invokes this canonical constructor and then provenance migration; it does not
  repeat artifact DDL.
- `R/provenance_store.R` owns the core `prov_*` schema and provenance schema
  version. The narrowly scoped `prov_registry_mutations` extension is owned by
  `R/registry_materialization.R` together with its replay behavior.
- Specialized registries such as feature sets, cell vectors, motifs, and
  cell-set recipes own only their named tables in their corresponding source
  files.
- A `CREATE TABLE` contract may occur once under `R/`. Fresh creation and
  migration must call the same owner instead of copying SQL into callers.

## Generated references

- `R/operation_docs.R` is generated exclusively by
  `inst/dev/generate_operation_docs.R` from `.wb_op_catalog()` through
  `wb_op_interface()`. It contains documentation aliases, never runtime
  function implementations.
- Operation, getter, plot, wrangler, primitive, artifact-type, parameter,
  recipe, unified semantic, and compatibility references under `docs/` are
  generated by their named catalog writer functions. Catalog implementation
  files are authoritative; generated Markdown/JSON is not a second runtime
  source.
- Generated text files carry a source/regeneration header when the format
  permits; generated JSON carries its schema version and generation timestamp.
  All generated references must be refreshed through the documented writer.
  Manual code must not be placed in a generated file.

The canonical release suite executes `test_source_ownership_contract()`, which
scans top-level functions and `CREATE TABLE` constructors, verifies the owner
map above, checks generated/manual separation, and exercises matrix-fragment
registration against both fresh and legacy schemas.
