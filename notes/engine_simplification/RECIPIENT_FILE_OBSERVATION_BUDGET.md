# Initial actual file-inventory reuse: prospective recipient budget

Before implementation: recipient elapsed>=10-percent below the qualified3066
baseline51.749s (target<=46.5741s), fewer actual bytes hashed, and whole-process
peak RSS<=matched old+10 percent. No new performance claim. Prior overall
workflow/recipient budget misses are not waived.

Recipient already owns a complete actual file-SHA inventory before checks and
an independently recomputed full inventory afterward. Retain only<=64KiB of
compact initial actual file observations in this lexical report lifetime.
Every reuse must freshly validate containment, normalized exact path and file
type. Existing file-tree identity enumeration/resolution/order/framing remains
fresh. No expected checksum, file timestamp or source-association verdict is
cached. File sizes may prioritize which initial observations fit, never prove
content or authorize a checksum match. Oversized entries/cap misses use the
existing full file hash, without a new rejection.

Private plumbing only: optional internal file-hash function on existing
file-tree/path/payload identity helpers; only recipient validation's actual
claim paths supply the report-local function. All nonrecipient, fitting,
promotion, recovery, transferred-input and ordinary calls keep the default.
Physical HDF metadata/finite/hash validation is untouched. Both full recipient
fingerprints MUST always use the original hash function; the final fingerprint
never uses initial observations. Any changed filesystem evidence still fails
the whole report, including changes after a reused individual claim check.

This is retrospective complete-report verification, not a new guarantee against
transient changes restored before final authentication or live raw-file editing
of an already-open immutable SQLite view. No public callback, persisted cache,
identity scheme, scientific setting or global cache service is introduced.

Replacement ledger (all inside wb_bundle_validation_report): artifact output
model/path and generic payload claims; entity-binding matrix/space/model/
artifact claims; provenance snapshot path claims; bundled source checksums;
and durable physical content-coverage matrix/space/model/artifact claims.
Unchanged HDF payload metadata/finite/hash validators do not receive the
optional function. The only generic forwarding points are file-tree hashing,
path identity, and matrix/model branches of payload identity. DefaultNULL
preserves all other callers. No function or observation enters the report,
wire, primitive, receipt, checkpoint or connection attributes.

Ledger admission accounts the new entry before growing the bounded list;
retained metadata stays<=64KiB. Candidate/previous lists plus bounded sorting
scratch may coexist transiently (source-informed target<1MiB, not a universal
RSS claim). Initial inventory paths/info/hash-vector retain their original
existing lifetime and framing, not an extra complete inventory copy.
